# المعمارية التقنية — ALIOUA BTP

## الهدف
نظام داخلي لمتابعة الملاحظات والمهام والتقدم في الورش، وربط كل سجل بموقعه ضمن شجرة: مشروع ← مبنى ← طابق ← مساحة/عنصر. هذا تنظيم معلومات مستلهم من BIM، وليس برنامج نمذجة BIM.

## المكونات
- **Backend:** Django + Django REST Framework، مسؤول عن البيانات المشتركة والمصادقة والصلاحيات والتحقق وسجل التدقيق والتقارير.
- **Web:** React + Vite، واجهة عربية RTL افتراضيًا مع خيار الفرنسية.
- **Mobile:** Flutter، لتسجيل الملاحظات والصور في الموقع مع قاعدة محلية وطابور مزامنة.
- **Database:** SQLite كبداية للتطوير والاستخدام الداخلي المحدود، مع إبقاء ORM قابلاً للانتقال إلى PostgreSQL.
- **Files:** تخزين محلي على خادم الشركة، مع التحقق من نوع الملف وحجمه وضغط الصور ونسخ احتياطي مستقل.

## حدود المسؤولية
الخادم هو مصدر الحقيقة للبيانات المشتركة. الويب والموبايل لا يتصلان بقاعدة البيانات مباشرة؛ كل العمليات المشتركة تمر عبر REST API.

## هيكل البيانات المنطقي
Project يحتوي Buildings؛ كل Building يحتوي Levels؛ كل Level يحتوي Spaces. Issue وTask وProgress وPhoto ترتبط بالمساحة، مع تسجيل المستخدم الذي أنشأ أو عدّل السجل. AuditLog يحتفظ بملخص العملية والكيان والفاعل والوقت.

## الأدوار
- Admin: إدارة المستخدمين والإعدادات والبيانات.
- Manager: الإشراف على المشروع والموارد والتقارير.
- Engineer: إدارة الملاحظات والمهام والتقدم حسب الصلاحيات.
- Inspector: تسجيل الملاحظات وتحديث نتائج المعاينة.
- Viewer: قراءة البيانات والتقارير المسموح بها فقط.

يجب فرض الصلاحيات في الخادم، وليس إخفاء الأزرار في الواجهة فقط. كما يجب تقييد الاستعلامات بالمشروع المصرح به للمستخدم قبل اعتبار النظام صالحًا لعدة مشاريع أو جهات.

## المزامنة دون اتصال
عند تنفيذ الموبايل:
1. ينشئ الجهاز UUID محليًا لكل عملية.
2. تحفظ العملية في SQLite بحالة pending.
3. ترسل العمليات عند عودة الاتصال.
4. يمنع الخادم تكرار العملية باستخدام UUID/idempotency key.
5. تطبق سياسة آخر تعديل يفوز عند التعارض، مع الاحتفاظ بسجل التعارض والتغييرات المهمة.
6. لا تحذف البيانات المحلية قبل تأكيد الخادم.

## الملفات والصور
التحقق من الامتداد والحجم ومحتوى الملف الفعلي قبل الحفظ. ضغط الصور قبل الرفع مع الحفاظ على نسخة مناسبة للعرض. لا ترفع ملفات قواعد البيانات أو ملفات البيئة أو صور مواقع حقيقية إلى مستودع Git العام.

## الأمان
- كلمات المرور عبر نظام Django hashing.
- JWT access/refresh مع مدد صلاحية مناسبة.
- الأسرار في متغيرات البيئة فقط.
- HTTPS عند الوصول عبر الإنترنت.
- صلاحيات على مستوى الدور والكائن والمشروع.
- سجل تدقيق للعمليات الحساسة.
- نسخ احتياطي واختبار استعادة دوري.

هذه بنية مستهدفة؛ لا تعتبر أي وظيفة منفذة لمجرد ورودها في الوثيقة. راجع README وحالة التنفيذ الفعلية.

## الاستضافة المجانية
الخيار الأساسي الأكثر ضمانًا للمجانية هو خادم تملكه الشركة داخل شبكتها. استضافة الواجهة على Vercel أو Netlify قد تناسب الخطط المجانية مع حدود استخدام متغيرة. لا نفترض أن استضافة Django أو تخزين ملفات media دائمًا مجانية على Render أو Fly.io؛ يجب التحقق من الشروط الحالية وعدم إدخال بطاقة بنكية أو تفعيل خدمة مدفوعة.
