# ALIOUA BTP — Suivi & Coordination

تطبيق داخلي لمتابعة الملاحظات والمهام والتقدم في مواقع البناء، يربط المعلومات بالمشروع والمبنى والطابق والمساحة. هذا النظام مستوحى من تنظيم معلومات BIM، لكنه ليس برنامج BIM ولا يحتوي على نمذجة ثلاثية الأبعاد أو IFC ضمن MVP.

## المستودع

- `backend/`: Django REST API، JWT، صلاحيات حسب الدور، سجل تدقيق، تقارير، QR.
- `web/`: React + Vite، واجهة عربية RTL متجاوبة.
- `mobile/`: Flutter، تسجيل الدخول وتسجيل الملاحظات محلياً عبر SQLite.
- `docs/`: معمارية النظام وخطة التنفيذ.

## ما هو موجود الآن

- نماذج المستخدمين والمشاريع والمباني والطوابق والمساحات والملاحظات والمهام والصور والتقدم وسجل التدقيق.
- API أولي للمصادقة JWT وCRUD والصلاحيات الأساسية.
- مخطط OpenAPI وواجهة Swagger.
- نقاط أولية للوحة التحكم، تصدير Excel/PDF، وQR للمساحات.
- واجهة ويب أولية فيها تسجيل دخول ولوحة مؤشرات متصلة بالـ API.
- تطبيق Flutter أولي: تسجيل دخول، حفظ ملاحظة دون اتصال، التقاط صورة محلية، ومحاولة مزامنة السجل يدوياً.
- أمر بيانات تجريبية وCI مجاني لفحص Backend.

**مهم:** هذه نسخة تطوير أولية وليست إصدار إنتاج جاهزاً. لم يتم بعد التحقق من بناء الويب أو APK في بيئة CI. مزامنة صور الهاتف، المزامنة التلقائية، الواجهات التفصيلية لكل الشاشات، عزل المستخدمين حسب المشروع، وإنهاء الترجمة الفرنسية ما زالت أعمالاً قادمة. PDF الحالي يستخدم خطوط ReportLab الافتراضية وقد لا يعرض النص العربي بشكل صحيح على كل الأنظمة.

## التقنيات المجانية

- Python + Django + Django REST Framework + SQLite.
- React + Vite + Axios + Recharts + Lucide.
- Flutter + sqflite + image_picker.
- ReportLab + openpyxl + qrcode + Pillow.
- GitHub Actions لفحوصات المستودع العام ضمن الحدود المجانية المطبقة على الحساب.

جميع المكتبات مفتوحة المصدر. لا توجد خدمة مدفوعة إلزامية.

## تشغيل Backend محلياً

```bash
cd backend
python -m venv .venv
# Linux/macOS/Termux
source .venv/bin/activate
# Windows PowerShell
# .venv\\Scripts\\Activate.ps1
pip install -r requirements.txt
```

انسخ `.env.example` إلى `.env`، ثم عيّن قيمة `DJANGO_SECRET_KEY` عشوائية بطول 50 حرفاً على الأقل. بعد ذلك:

```bash
python manage.py makemigrations core
python manage.py migrate
python manage.py check
python manage.py seed_demo
python manage.py runserver 0.0.0.0:8000
```

حسابات البيانات التجريبية الجديدة:
- admin@alioua.local
- manager@alioua.local
- engineer@alioua.local

كلمة المرور الأولية: `ChangeMe123!` — محلية للتجربة فقط، غيّرها فوراً ولا تستخدمها على خادم مكشوف للإنترنت.

## تشغيل Web

```bash
cd web
npm install
cp .env.example .env
npm run dev
```

اضبط `VITE_API_URL` في `.env` إلى عنوان Backend الذي يمكن للمتصفح الوصول إليه. عنوان `127.0.0.1` يعمل فقط إذا كان الخادم على الجهاز نفسه.

## تشغيل Mobile وبناء APK

```bash
cd mobile
flutter create .
flutter pub get
flutter run --dart-define=API_BASE=http://192.168.x.x:8000/api
flutter build apk --release --dart-define=API_BASE=http://192.168.x.x:8000/api
```

غيّر عنوان IP إلى عنوان حاسوب الخادم داخل شبكة الشركة. ناتج APK يوجد عادةً في `build/app/outputs/flutter-apk/app-release.apk`. في النسخة الحالية تحفظ صورة الملاحظة محلياً؛ رفع الصورة ومزامنتها مع الخادم لم يكتمل بعد.

## الاستضافة المجانية

الخيار الأكثر ضماناً للتحكم في التكلفة هو تشغيل Backend وقاعدة البيانات والملفات على جهاز تملكه الشركة داخل شبكتها، مع نسخ احتياطي محلي. يمكن نشر واجهة React على Vercel أو Netlify ضمن الخطط المجانية، لكن الحدود وسياسات الاستخدام قابلة للتغيير. لا نفترض أن استضافة Django أو تخزين ملفات `media/` دائم مجاناً على Render أو Fly.io؛ تحقق من الشروط الحالية قبل النشر، ولا تستخدم أي خطة تتطلب بطاقة بنكية أو دفعاً.

## الأمان والبيانات

- لا ترفع `.env` أو `db.sqlite3` أو `media/` أو بيانات حقيقية إلى Git.
- المستودع عام؛ لا تضع فيه صور مواقع أو بيانات موظفين أو أسراراً.
- SQLite مناسبة للتطوير والاستخدام الداخلي البسيط؛ قيّم PostgreSQL عند زيادة التزامن.
- صلاحيات الدور موجودة كبداية، لكن عزل السجلات حسب المشروع لم يكتمل بعد؛ لا تستخدم النظام حالياً لعدة جهات مستقلة.
- خذ نسخاً احتياطية من قاعدة البيانات ومجلد الملفات واختبر الاستعادة.
