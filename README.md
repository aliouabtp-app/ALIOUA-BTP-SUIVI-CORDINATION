# إتقان – ALIOUA BTP | Suivi & Coordination

تطبيق داخلي لإدارة ومتابعة مواقع البناء: الملاحظات، المهام، تقدم الإنجاز، المخططات، والمساحات. يستلهم تنظيم المعلومات من مبادئ BIM عبر ربط كل معلومة بمشروع ومبنى وطابق ومساحة، لكنه **ليس برنامج BIM ولا بديلاً عن Revit**.

## بنية المستودع

- `backend/`: Django + Django REST Framework، JWT، صلاحيات، سجل تدقيق، تقارير PDF/Excel، QR.
- `web/`: React + Vite + Recharts، واجهة RTL عربية متجاوبة.
- `mobile/`: Flutter، SQLite محلية، التقاط صور، QR، عمل دون اتصال ومزامنة.
- `docs/`: المعمارية، مرجع API، وخطة التنفيذ.

## الوظائف الموجودة في النسخة الحالية

### Backend
- نماذج المستخدمين والأدوار: Admin وManager وEngineer وInspector وViewer.
- المشروع ← المبنى ← الطابق ← المساحة.
- إدارة الملاحظات والمهام والصور وسجلات التقدم.
- صلاحيات حسب الدور، كلمات مرور مشفرة، Soft Delete، وAudit Log.
- API موثق عبر OpenAPI/Swagger.
- تصدير أولي لتقارير الملاحظات PDF وExcel.
- إنشاء QR للمساحة.

### Web
- تسجيل الدخول ولوحة مؤشرات ورسوم بيانية.
- إدارة الملاحظات مع الصور والحالات والأولويات.
- لوحة مهام Kanban بألوان هادئة وحالات واضحة.
- إنشاء حسابات الموظفين وتغيير الأدوار وتفعيل/تعطيل الحساب (لـ Admin).
- إنشاء المشاريع والمباني والطوابق والمساحات حسب صلاحيات الدور.
- رفع مخططات PDF أو صور؛ عرض PDF والصور، وتحديد pins على المخططات المصورة.
- تحويل أولي محلي من DXF إلى GLB، مع ربط النموذج بالطابق وعرضه في Three.js؛ يمكن ضبط الوحدات وارتفاع الجدار وسماكته وطبقة الجدران.
- عرض شجرة المشروع ورموز QR للمساحات.
- تسجيل تقدم الإنجاز لكل مساحة وعرض آخر نسبة مسجلة.

### Mobile
- تسجيل الدخول وحفظ الملاحظات والصور محلياً عند انقطاع الشبكة.
- مزامنة الملاحظات والصور عند عودة الاتصال.
- مسح QR لملء معرّف المساحة في الملاحظة.
- عرض المهام وإنشاؤها وتعديل الحالة ونسبة الإنجاز.
- حفظ المهام وتعديلات الحالة/الإنجاز في SQLite أولاً، ثم مزامنتها تلقائياً عند عودة الشبكة.
- تُخزّن قائمة المساحات محلياً بعد أول اتصال ناجح؛ لذلك يجب تحميل المساحات مرة واحدة قبل استخدام إنشاء المهام دون اتصال.

**حالة المنتج:** MVP قيد التطوير والاختبار، وليس إصدار إنتاج نهائياً. يجب اختبار المزامنة على أجهزة فعلية، ومراجعة الصلاحيات وعزل البيانات والنسخ الاحتياطي قبل استخدامه مع بيانات موقع حساسة. الترجمة الفرنسية الكاملة، ومحرر 3D متقدم، وتحويل PDF/الواجهات/المقاطع إلى هندسة، ودعم IFC لم تكتمل بعد. التحويل المتاح حالياً DXF فقط، ويستخرج LINE وLWPOLYLINE وPOLYLINE إلى جدران مستطيلة موحدة. لا يستنتج الأبواب والنوافذ والأعمدة أو مناسيب الطوابق تلقائياً؛ يلزم تدقيق النموذج ومقارنته بالواجهات والمقاطع قبل الاعتماد. لا تعتبر النماذج ثلاثية الأبعاد الناتجة مستندات تنفيذية معتمدة دون مراجعة هندسية بشرية.

## تشغيل Backend محلياً

```bash
cd backend
python -m venv .venv
# Linux / macOS / Termux
source .venv/bin/activate
# Windows PowerShell
# .venv\\Scripts\\Activate.ps1
pip install -r requirements.txt
```

انسخ `.env.example` إلى `.env` وأنشئ `DJANGO_SECRET_KEY` عشوائياً وقوياً، ثم:

```bash
python manage.py makemigrations core
python manage.py migrate
python manage.py check
python manage.py seed_demo
python manage.py runserver 0.0.0.0:8000
```

حسابات البيانات التجريبية:
- `admin@alioua.local`
- `manager@alioua.local`
- `engineer@alioua.local`

كلمة المرور الأولية للتجربة المحلية فقط: `ChangeMe123!`. غيّرها قبل أي استخدام فعلي، ولا تعرض خادم التطوير مباشرة للإنترنت.

## تشغيل Web

```bash
cd web
npm install
cp .env.example .env
npm run dev
```

اضبط `VITE_API_URL` إلى عنوان API الذي يمكن للمتصفح الوصول إليه. عنوان `127.0.0.1` يشير إلى الجهاز الذي يعمل عليه المتصفح، وليس تلقائياً إلى جهاز الخادم داخل الشبكة.

## تشغيل Mobile وبناء APK

```bash
cd mobile
flutter create .
flutter pub get
flutter run --dart-define=API_BASE=http://192.168.x.x:8000/api
flutter build apk --release --dart-define=API_BASE=http://192.168.x.x:8000/api
```

استبدل عنوان IP بعنوان جهاز الخادم داخل شبكة الشركة. يمكن أيضاً ضبط عنوان API من شاشة تسجيل الدخول. ملف APK المحلي يوجد عادةً في:

`mobile/build/app/outputs/flutter-apk/app-release.apk`

يُبنى APK عبر GitHub Actions كـ Artifact باسم `alioua-btp-android-apk`. احتفاظ GitHub بالـ Artifact مؤقت (30 يوماً في إعدادات سير العمل الحالية)، وحدود Actions المجانية تعتمد على نوع المستودع والحساب وسياسة GitHub.

## الاستضافة المجانية

**الخيار الأكثر قابلية للتحكم:** تشغيل Django وSQLite ومجلد `media/` على جهاز داخل شبكة الشركة، مع نسخ احتياطي محلي منتظم.

يمكن استضافة الواجهة الثابتة على Vercel أو Netlify ضمن خططهما المجانية، لكن الحدود وسياسات الاستخدام قابلة للتغيير. لا تفترض أن خدمة Backend مجانية تعني تخزين ملفات دائم: بعض الخطط المجانية توقف الخادم عند الخمول أو لا توفر قرصاً دائماً. قبل اختيار Render أو Fly.io أو أي مزود، تحقق من:
- هل الخطة مجانية فعلاً ولا تتطلب بطاقة؟
- هل قاعدة البيانات والملفات دائمة أم تُحذف عند إعادة التشغيل؟
- ما حدود ساعات التشغيل والتخزين والنقل؟
- هل يمكن تنزيل نسخة احتياطية واستعادتها؟

لا ترفع قاعدة البيانات أو الصور الحقيقية إلى GitHub. المستودع عام، لذلك لا تضع فيه أسراراً أو بيانات موظفين أو صور مواقع خاصة.

## الأمان والنسخ الاحتياطي

- لا ترفع `.env` أو `db.sqlite3` أو `media/` أو مفاتيح API إلى Git.
- استخدم HTTPS عند الوصول من خارج شبكة الشركة.
- SQLite مناسبة للتطوير والاستخدام الداخلي البسيط؛ قيّم PostgreSQL عند زيادة التزامن.
- عزل السجلات حسب المشروع لم يكتمل بعد؛ لا تستخدم النظام حالياً كمنصة متعددة الشركات.
- انسخ قاعدة البيانات ومجلد الملفات معاً، واختبر استعادة النسخ الاحتياطية دورياً.
- لا تعتمد تقارير PDF رسمياً قبل التحقق من ظهور الخط العربي بشكل صحيح على الخادم.

## المراحل اللاحقة

1. إكمال الترجمة الفرنسية لجميع الشاشات.
2. تحسين عارض المخططات ودعم pins على PDF بدقة.
3. توسيع تحويل DXF إلى محرر 3D يسمح بتعديل الجدران وفتحات الأبواب والنوافذ وربط المقاطع والواجهات؛ ثم دراسة تتبع PDF/الصور مع معايرة مقياس واضحة وتحقق هندسي بشري.
4. دراسة IFC عبر IfcOpenShell في مرحلة منفصلة.
5. نسخ احتياطي محلي تلقائي وإشعارات بريد مجانية ضمن حدود Gmail SMTP.
